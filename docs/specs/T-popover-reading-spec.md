# T-popover-reading 規格

董事會於 2026-11-02 明確批准「批准计划，开始实作」。
本單只有一個完整垂直切片，不另拆佈局、互動與測試工單。

## 問題與解法

長 Answer 在狹小 Popup 中需要大量捲動。在同一 Popup 增加手動展開閱讀與收起，
加寬並收起非正文區，保留完整 Answer、可見工具列與原有縮放。

## 使用者故事

1. 閱讀者可在完成 Answer 後原地展開，減少換行與非正文佔用。
2. 閱讀者可收起回到輸入，不丟失草稿、不重新發送。
3. 閱讀者可捲動長 Answer 並隨時複製完整原始 Markdown。
4. 鍵盤使用者可操作切換、看到焦點，且不進入隱藏控制。
5. 小螢幕或高縮放使用者仍可使用必要控制，不以縮字換取空間。
6. 關閉再開 Popup 時回到緊湊模式，不新增偏好設定。

## 已批准決策

遵循[實作計畫](../plans/2026-11-02-popover-reading-implementation-plan.md)，
包含 560px 未縮放閱讀基準、800px 可見寬上限、單一主要垂直捲動區、
文件內模式狀態、重繪整合及閱讀錨點的 should 要求。
維持原有字體、人設、複製、提交與 Handoff。

## 測試接點與證據

以既有 Popup DOM 行為測試為主要自動化接點，尺寸計算沿用縮放測試。
測試可觀察結果而非私有函式或 CSS 常數。
真實 action Popup 六組尺寸驗收是獨立的必要證據，不以一般 HTML 代替。
完整 M1–M7 與 S1 測試條件以已批准實作計畫第 6 節為準。

## 範圍外

不新增閱讀頁、側欄、摘要、依賴、持久設定或權限。
不修改 SW、adapter、共享業務狀態、timeout、Options 或 CSP。
