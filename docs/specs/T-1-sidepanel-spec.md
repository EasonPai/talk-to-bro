# T-1 Popup 釘選與側邊欄規格

## 問題

Chrome 工具列 Popup 在使用者切換分頁或點擊外部時關閉，無法在閱讀網頁時持續查看 Bro 的回答。

## 解決方式

保留 Popup，提供釘選操作切換到 Chrome 側邊欄。側邊欄在同一視窗切換分頁時持續可用；取消釘選切回 Popup。保存模式、未送出草稿、最近 Talk 與完整回答。重啟 Chrome 不自動開啟介面，下次主動開啟時恢復模式和內容。

## 使用情境

1. 使用者可在 Popup 中釘選，繼續在側邊欄閱讀回答並切換分頁。
2. 使用者可取消釘選回到 Popup，保留草稿與回答。
3. 使用者可關閉側邊欄而不取消釘選，下次開啟時恢復。
4. 使用者可在 Chrome 重啟後主動開啟 Talk To Bro，恢復上次模式與內容。
5. 使用者在多個視窗共享草稿與回答。切換模式只影響發起操作的視窗。
6. 使用者送出被拒絕時保留草稿；成功接受後，已送文字與新的草稿分開。
7. 使用者在操作或保存失敗時看到錯誤，原畫面及內容保留。
8. 未完成的 Talk 在瀏覽器重啟後遵循既有中斷與 Handoff 規則，不自動重送。

## 實作決策

- 以共用介面模板建置 Popup 與側邊欄入口，保留現有互動與視覺風格。
- Service Worker 是狀態唯一寫入者。模式和草稿使用獨立的 UI 狀態，避免覆蓋 Talk runtime。
- UI 狀態更新需序列化，提交後只清除對應版本的草稿。多視窗以最後成功保存為準。
- 功能最低支援 Chrome 141，並新增側邊欄權限。不放寬 CSP。
- 不在模式切換或恢復時新增或重送 Talk。
- 先以真實 Chrome 驗證釘選、取消釘選與重新啟動行為；若關鍵路徑不可行，停止並回報，不自行改變需求。

## 測試決策

以可觀察行為為準，沿用現有 Popup、storage、runner 與 reconcile 測試。真實隔離 Chrome for Testing 驗證跨分頁、雙入口、完整瀏覽器重啟、快捷鍵、雙視窗及真實 Talk；模擬測試不能代替真實瀏覽器驗證。必須與建議測項及詳細通過條件以[核准計畫](../plans/2026-11-03-T-1-sidepanel-session-plan.md#驗收測項)的 M1–M12、S1–S2 為準。

## 不在範圍內

多筆對話工作區、跨裝置同步、網頁內浮動視窗、歷史搜尋、新視覺系統，以及跨重啟精準恢復捲動位置、焦點或閱讀展開狀態。
