# 隨身聊 Popup 設計簡報

- 日期：2026-10-29
- 狀態：CONFIRMED — 使用者已確認設計簡報，明確要求停在規劃階段；未授權實作。
- 範圍：`src/popup/` 的設計規劃，不修改 HTML、CSS、TypeScript、素材或 CSP。
- 模式：Operate。主要任務是快速遞出 Talk、讀懂完整 Answer，不是遊戲體驗。

## 已確認的需求

- 以 `PRODUCT.md` 及 PRD v1.1 為產品依據，保留 Pip／Bro 人設與既有功能。
- 使用者選擇閱讀優先，角色精巧但有存在感；允許重新安排 Popup 結構。
- 保留快捷鍵、Enter 送出、Shift+Enter 換行、輸入法組字保護、
  300 字元上限、Last Talk 恢復、完整 Markdown Answer 與複製功能。
- 不改 Service Worker、Talk 狀態機、送出／逾時規則、Handoff 的
  1.5 秒倒數、取消、延後執行或已執行結果。

## 現況與證據邊界

- 已閱讀目前的 `src/popup/popup.html`、`popup.css`、`popup.ts`。
- 現有樣式為 360px 寬的深色面板；Pip 用 emoji 表現，
  Answer 本文 12px、表格 11px，閱讀區最大高度固定 240px。
- 當前原始碼已有 `followActiveTabZoom` 呼叫；不據此推定縮放問題已修復。
- CfT 156.0.8078.47 可連線，但沒有已開啟的 extension Popup；
  未發現受版控的截圖基準。本方案尚未對實際渲染驗證。
- 避免為了取得基準而建置、重新載入擴充套件、送出真實 Talk，
  或干擾其他工作的瀏覽器與未提交檔案。

## 建議方向：小弟遞話，老大答覆

沿用現有深色底與冷色重點，不另造一套視覺世界。將可愛、
Pixel Art／Roguelike 身分集中在角色、局部邊角與狀態回饋；
讓答案區像清楚的閱讀頁，而不是地下城場景。

Pip 保持同一角色，只換姿態與狀態標記，不再靠不同 emoji
代替整個角色。現有狐狸 emoji 不視為已核准的角色物種；
最終造型及可用素材須另行確認，不在本輪製作。
Bro 以既有「老大／Answer」標題及措辭表現，不新增占空間的大頭像。

## 資訊與版面

依序保留三個穩定區域，不採聊天泡泡、分頁切換或可折疊輸入：

1. **狀態列**：小型 Pip、簡短狀態文字及設定入口。
   等待與完成均由既有狀態驅動；不顯示假百分比或預估完成秒數。
2. **Talk 輸入區**：輸入框始終可見，字數及 Enter 提示集中在同一行。
   保留真實鍵盤操作，不新增送出按鈕、重試或追問行為。
3. **結果區**：Answer 出現後取得主要閱讀面積，標題與複製操作不隨
   長答案捲走；失敗時同一區域承載原因與既有 Handoff 控制。
   說明與操作不散落到重複的警示卡片。

開啟時仍能直接打字，收到答案時不任意搶走輸入焦點、不自動捲動到末尾。
既有 deferred Handoff 的焦點規則保持不變。
空白狀態不預留大型插畫或整塊空的 Answer 卡。

預設先以 400px 寬作候選，並檢查 360px 窄版；最終尺寸待實機確認，
不以硬加高度換取閱讀面積。結果區使用剩餘可用高度，不延續固定
240px 的閱讀上限；一般答案僅在結果區垂直捲動，避免雙層垂直捲軸。
超出 Chrome Popup 或可用螢幕限制時，操作仍須可見且可由鍵盤到達。

## 各狀態的呈現

| 狀態 | 畫面重點 | 不變的規則 |
| --- | --- | --- |
| 初次／待輸入 | Pip 待命、清楚輸入提示、300 字元計數 | 自動聚焦，不新增導覽流程 |
| 送出／等待／擷取 | 同一狀態列呈現真實階段，微小動態可停用 | 不提前顯示未完成 Answer，不改等待規則 |
| 完成 | 完整 Answer、穩定的複製入口及複製回饋 | 不摘要、不改寫、不變成多輪聊天 |
| 失敗／倒數 Handoff | 原因優先，Pip 情緒輔助；倒數與「留在這裡」清楚可見 | 倒數仍為 1.5 秒，不改自動切換政策 |
| 延後／取消／已執行 Handoff | 顯示儲存狀態對應的既有控制與結果 | 不重啟已取消的倒數，不謊稱複製成功 |
| 關閉再開 | 恢復 Last Talk 對應的輸入、答案或等待狀態 | 不重送 Talk，不重播入場動畫 |

未設定、未登入、DOM 不相容、額度與逾時仍各自保留可辨識的原因；
不全部改成一句人設笑話。文案若需調整，先確認，不自動改動事實訊息。

## 閱讀、操作與內容範圍

- Answer 使用一般中英文字型，本文候選為 14–15px、舒適行距；
  表格不靠縮小文字塞入。像素字型限必要標題或按鈕，不影響答案。
- 深色層次用來區分輸入、答案及狀態；狀態以文字加形狀／標記呈現，
  不只靠紅綠色。錯誤清楚但不讓整個 Popup 閃紅。
- 檢查單一單字、多字／片語、300 字元 Talk、短 Answer、
  多螢幕長 Answer、Markdown 標題／清單／表格與長連結。
  寬表格或程式碼只在必要的局部橫向捲動，不讓整個 Popup 撐寬。
- 焦點清楚可見，圖示入口有可理解名稱，主要操作不因放大而被裁切。
  等待狀態可供輔助技術辨識，但不反覆朗讀整段答案或每個倒數更新。
- 在實作階段驗證 100%、150%、200% 縮放及減少動態偏好；
  不把主動修復既有縮放或 Answer 讀回問題混入視覺變更。

## 邊界、取捨與後續門檻

- 400px 可能改善中英文及表格閱讀，但比現有 Popup 占空間；
  若實機遮擋感過強，回到 360px，不壓縮字級補償。
- 小角色避免搶走答案空間，但不會呈現完整角色場景。
  素材缺口保持明列，不以新創物種或大幅插畫補齊。
- 不動 Options、背景 Gemini 分頁、adapter、權限、儲存資料與 CSP；
  不新增歷史、Notion、聊天、遊戲進度或 API 整合。
- 本輪只確認設計簡報，不寫 `DESIGN.md`、方向契約、原型或實作程式。
  後續若要實作，需另存可執行計畫並取得明確授權。
- 後續視覺驗收須在隔離 CfT 檢查上述狀態、尺寸及長內容。
  對既有背景修復工作的依賴與結果另列，不以畫面正確推定送讀流程正確。
- 本簡報的 Schema／內容檢查不等於視覺驗收；本輪不執行 UI 測試，
  也不重建共享 Graphify 索引。
