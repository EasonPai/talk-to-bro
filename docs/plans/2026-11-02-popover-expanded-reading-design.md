# Popover 原地展開閱讀：短設計

日期：2026-11-02

工單識別：T-popover-reading

狀態：方案 A 已選定；本設計待董事會確認，尚未授權實作。

## 目的與範圍

長 Answer 在現有 Popover 中因寬度及非正文區域而需要大量捲動。
維持同一個工具列 Popup，加入手動切換的「展開閱讀／收起」；
不開新頁、不改為側邊欄、不切換 Bro Chat。既有像素人設與正文可讀字級保留。

## 方案比較與決定

| 方案 | 行為與取捨 |
|---|---|
| A：加寬＋閱讀模式（董事會已選） | 同時加寬並收起非正文區域，增加可視字數；需要處理模式切換及閱讀位置。 |
| B：只加寬 | 改動較少，但輸入及角色區域仍佔用高度，改善有限。 |

## 互動與佈局

- 完成的 Answer 工具列新增「展開閱讀」。預設仍為原有緊湊模式，不自動展開。
- 展開後收起角色敘述、上一則卡片與輸入區，保留緊湊標題、複製與「收起」控制；正文是主要且單一的垂直閱讀捲動區。
- 加寬只使用 Chrome Popup 容許且實際可用的空間，不承諾突破平台高度限制。寬度及高度算法由 Architect 根據現有縮放機制與實際 Popup 主機驗證後決定，不以拉大字體或提高縮放倍率冒充擴容。
- 收起恢復原有介面與未送出的輸入草稿。切換時盡量保持同一閱讀段落；文字重排時不要求絕對像素位置一致。
- 表格與程式碼保留區域內橫向捲動，不讓整個 Popup 出現橫向溢出。工具列在正文捲動時仍可用。

## 驗收條件

1. must：有完整 Answer 時可用滑鼠及鍵盤展開、收起；不建立新頁、視窗或側邊欄。
2. must：正常桌面空間下，展開模式增加正文可見空間；平台或螢幕限制時不裁切控制項、不溢出可用 Popup 範圍。
3. must：長中英文 Markdown、標題、清單、寬表格及程式碼保持完整；不摘要、不截斷、不改寫，也不縮小正文來換取空間。
4. must：複製內容與完整 Answer 一致；切換前後保留未送出草稿，不重新發送、不重啟請求。
5. must：只保留一個主要垂直閱讀捲動區；複製與收起控制不隨正文消失，鍵盤焦點可見，隱藏區域不可取得焦點。
6. must：100%、150%、200% 分頁縮放與小可用高度下，檢查尺寸、控制項可達性及區域溢出；包含實際擴充套件 Popup 主機驗證，不只獨立 HTML。
7. should：切換前後保持閱讀段落；無法精確定位時保留合理鄰近位置，不無故回到頂部。

## 非目標與待定事項

不更動背景狀態機、Gemini DOM 操作、timeout、Handoff、權限或 CSP；
不增加摘要、分頁、搜尋或新歷史功能。重新開啟 Popup 是否保留閱讀模式尚未由董事會指定；
本設計建議只保留於當次 Popup 生命週期，不新增持久設定，需隨本設計一併確認。
